# power-health

Telegram-бот, який пише в канал, коли вдома зникає або з'являється світло, і скільки часу його не було (або було).

## Як це працює

```
Android + MacroDroid  ──HTTPS──►  Cloudflare Worker + D1  ──►  Telegram-канал (сповіщення)
(датчик: на зарядці?)             (уся логіка, історія)   ◄──►  особистий чат власника (керування)
```

- **Телефон** вдома постійно стоїть на зарядці. MacroDroid миттєво надсилає подію, коли зарядку відключили або підключили, а раз на 15 хв шле heartbeat з поточним станом. Інструкція: [docs/macrodroid.md](docs/macrodroid.md).
- **Worker** приймає ці запити, рахує тривалості й пише в канал. Якщо подія загубилась, стан відновлюється з heartbeat. Раз на 5 хв cron перевіряє, чи телефон на зв'язку: після 45 хв тиші приходить «⚠️ Детектор не на зв'язку».
- **Короткі блимання стираються.** Якщо світло з'явилось менш ніж через 5 хв (`BLIP_MAX_MIN`), бот видаляє з каналу «🔴 Світло зникло», не пише «🟢 Світло з'явилось» і не записує це відключення в історію.
- **Звіти в канал** о 10:00 за Києвом: щопонеділка за минулий тиждень (Пн–Нд, по днях і порівняно з попереднім), 1-го числа — по 12 завершених місяцях. Без даних звіт не надсилається.
- **Графік відключень** з [SvitloPulse](https://svitlopulse.andrewboyko.name/api/) (відкритий API, без ключа): до «🔴 Світло зникло» додається «📅 За графіком: до 18:30», «⚠️ Аварійне відключення: графік не діє» або «ℹ️ Відключення поза графіком»; до «🟢 Світло з'явилось» — наступне відключення за графіком. Черга задається командою `/queue`. Якщо API не відповідає за 4 с, повідомлення йде без графіка.
- **Попередження**: за ~30 хв до відключення за графіком — «⏰ О 21:30 відключення за графіком, до 02:00» (лише коли світло є і графік діє).
- **Графік на завтра** о 22:00, щойно оператор його опублікує (перевіряємо кожні 5 хв до кінця доби).
- **Закріплене повідомлення** в каналі зі станом «зараз»: оновлюється раз на 5 хв і одразу після змін; якщо його видалити, бот створить нове. Для закріплення боту потрібне право «Редагувати повідомлення інших».
- Статична IP не потрібна: телефон сам ходить до Worker'а, а Telegram сам ходить до Worker'а через webhook.

## Доступ

- **Керувати ботом може лише власник** (`OWNER_USER_ID`) в особистому чаті з ботом. Повідомлення від будь-кого іншого бот ігнорує.
- **Сповіщення йдуть лише в один канал**: той, де власник написав `/activate`. Поки канал не активовано, сповіщення нікуди не надсилаються.
- `/activate` у каналі спрацює лише від тебе. Якщо Telegram показує автора допису, це має бути саме твій акаунт. Якщо допис іде від імені каналу, бот перевіряє, що ти власник (creator) цього каналу.
- Якщо бота додасть у канал хтось інший, бот одразу з нього вийде. З будь-яких груп він теж виходить.

## Команди (в особистому чаті з ботом)

Єдиний виняток — `/activate`: її пишуть у самому каналі.

| Команда | Що робить |
|---|---|
| `/status` | Чи є зараз світло, як довго, стан телефона, активний канал |
| `/stats` | % часу зі світлом, відключення і тренд: за 7 днів (по днях) і 12 місяців (по місяцях) |
| `/testStart` | Тестовий режим: запити телефона не пишуться в базу й не йдуть у канал, а приходять тобі з розбором (що сервер зробив би). Поточний стан не змінюється |
| `/queue 20.1` | Твоя черга для графіка відключень (`/queue` — показати, `/queue off` — вимкнути) |
| `/testStop` | Вимкнути тестовий режим. Наступний heartbeat оновить стан (з `changed_at` — з точним часом) |

Службові повідомлення приходять тобі в особисті, а не в канал: нагадування про тестовий режим (через 1 год, далі раз на 3 год) і попередження, якщо бота прибрали з каналу.

## Налаштування з нуля

### 1. Telegram

1. У [@BotFather](https://t.me/BotFather) створи бота командою `/newbot` і збережи токен.
2. Напиши своєму боту `/start`. Без цього бот не зможе писати тобі в особисті.
3. Відкрий `https://api.telegram.org/bot<TOKEN>/getUpdates` і знайди `message.from.id`. Це `OWNER_USER_ID`, тобто твій ID.
4. У @BotFather: `/setjoingroups` → вибери бота → **Disable**.

### 2. Cloudflare

```bash
npm install
npx wrangler login
npx wrangler d1 create power-health   # встав database_id у wrangler.jsonc
npm run db:migrate
npm run deploy                        # покаже URL: https://power-health.<акаунт>.workers.dev
```

### 3. Секрети

```bash
cp .env.example .env    # заповни; секрети згенеруй через: openssl rand -hex 32
npx wrangler secret bulk .env
```

### 4. Підключити webhook і меню команд

```bash
curl -X POST https://power-health.<акаунт>.workers.dev/admin/setup \
  -H "Authorization: Bearer <WEBHOOK_SECRET>"
```

Цю команду треба запускати повторно щоразу, коли змінюєш `WEBHOOK_SECRET` або `OWNER_USER_ID`. Після цього напиши боту `/status`, і він має відповісти.

### 5. Канал

1. Додай бота в канал адміністратором з правами «Публікувати повідомлення» і «Видаляти повідомлення».
2. Напиши в каналі `/activate`.
3. Бот видалить твій допис `/activate` (для цього й потрібне право на видалення) і опублікує «✅ Тепер тут будуть сповіщення про світло». Тобі в особисті прийде підтвердження.

Щоб змінити канал, повтори ці кроки з новим каналом.

### 6. Телефон

Налаштуй MacroDroid за інструкцією [docs/macrodroid.md](docs/macrodroid.md).

## Розробка

```bash
npm test            # vitest; D1 емулюється через node:sqlite з тими ж міграціями
npm run typecheck
npm run dev         # локально; секрети бере з .dev.vars
```

Логи задеплоєного Worker'а можна дивитися через `npx wrangler tail`.

### Структура

| Файл | Що в ньому |
|---|---|
| `src/index.ts` | HTTP-маршрути (`/device/*`, `/telegram`, `/admin/setup`) і cron |
| `src/device.ts` | Обробка подій і heartbeat від телефона |
| `src/bot.ts` | Команди бота, доступ, активація каналу, пауза |
| `src/cron.ts` | «Детектор не на зв'язку», нагадування про паузу |
| `src/state.ts` | Стан і історія періодів у D1 |
| `src/stats.ts` | Текст `/stats`: тиждень по днях, рік по місяцях |
| `migrations/` | Схема D1 |

### HTTP API для телефона

`POST /device/event` (миттєва подія) і `POST /device/heartbeat` (раз на 15 хв), заголовок `X-Device-Key: <DEVICE_SECRET>`:

```json
{ "charging": true, "ts": 1762336800, "battery": 87 }
```

- `ts` — це час на телефоні в секундах або мілісекундах. Сервер упорядковує запити за ним, тому повтори й запізнілі запити нічого не ламають.
- `ts` і `battery` необов'язкові. Без `ts` сервер бере свій поточний час.
